⚡ Capabilities

Built for scale from day one

Every layer is designed for distributed processing — from the API to the Ray cluster.

⚡
True parallelism

Ray remote functions run simultaneously across all workers. ray.wait() collects results as they arrive — no sequential blocking.

📊
Three operations

Sum numeric columns, compute weighted means across unequal chunks, or count rows matching a filter — across any file size.

🔄
Live progress

Redis tracks completion per chunk with atomic WATCH/MULTI/EXEC updates. The UI polls every 2.5s and animates progress in real time.

🛡️
Fault tolerant

Each Ray task retries up to 2 times automatically. Failed jobs surface a sanitised error message — no stack traces exposed to clients.

📁
Multi-format

CSV (UTF-8 with latin-1 fallback), JSON arrays, and JSON Lines. All formats are normalised to row-bounded CSV chunks internally.

🔐
Secure by default

Content-type allowlist, 500 MB size cap, UUID-only paths (no traversal), optional API key gate, and configurable CORS origins.

🗺 Workflow

Three steps, zero config

From raw file to aggregated result in under a minute.

📤
1. Upload

POST your CSV or JSON file with an operation and column name. The API validates, stores, and splits it into configurable chunks.

⚡
2. Distribute

Ray workers process all chunks in parallel. A ResultAggregator actor collects partial results as they arrive using ray.wait().

✅
3. Result

Poll /status/{id} for live progress, then fetch the final aggregated value from /result/{id} when complete.
